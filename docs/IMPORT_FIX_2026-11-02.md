# 자료 등록 중 Failed to fetch 수정

미리보기 후 등록할 때 연결 오류가 발생한다는 제보를 기준으로 확인했습니다. 기존 Worker의 지난 24시간 집계에서 `exceededResources` 오류 6건을 확인했습니다. 요청별 로그는 수집하지 않아 이 집계만으로 개별 등록 요청과 일대일 대응을 확정할 수는 없습니다. [Cloudflare 자원 제한 오류](https://developers.cloudflare.com/workers/observability/errors/)

등록 준비 코드가 각 학생의 모든 선택과목에 대해 전체 분반을 순회하며 같은 키를 반복 정규화하고 있었습니다. 학생도 매번 기존 목록 전체를 검색했습니다. `prepareImport`에서 학생의 원본 학번·현재 학번과 분반의 원본 키를 한 번 색인한 뒤 조회하도록 변경했습니다. 학생 번호 변경 시 색인을 함께 갱신하고, 모호한 연결·중복 학생은 계속 거부합니다. 과목 배정 계산이나 화면 구성은 변경하지 않았습니다.

등록은 기존 D1 단일 batch 트랜잭션을 유지합니다. 등록 전 백업, 학기·revision 충돌 검사, 로그인 세션 가드, 웹 수정값·학적·학생 ID 보호를 유지하며 새 스키마·DB·프로젝트는 필요하지 않습니다. [D1 batch 제한](https://developers.cloudflare.com/d1/platform/limits/)

연결 실패나 플랫폼의 HTML 오류 응답도 읽을 수 있는 한국어로 표시합니다. 실패 시 선택한 파일·미리보기를 유지하고 입력 잠금을 해제합니다. 저장 요청을 자동 재전송하지 않으며, 응답을 받지 못한 경우 재시도 전에 학생 목록에서 저장 여부를 확인하도록 안내합니다.

## 검증 범위

- 첨부된 원본 XLSX 5개는 수정하지 않고 로컬 파서·Miniflare D1 및 가상 `.test` 출처 브라우저로 미리보기·등록을 확인합니다. 원본 개인정보를 Git·Actions artifact에 포함하지 않습니다.
- 공개 회귀 테스트는 전부 코드로 생성한 가상 학생·분반·교사 자료를 사용합니다. 대량 등록, 수강 배정 일치, 재등록 시 웹 수정값·학적 보호, 실패 후 자료 유지와 네트워크 오류 안내를 확인합니다.
- 기존 운영 DB의 자료 수·활성 학기·revision·인증 버전을 읽기 전용으로 비교합니다. 운영 비밀번호는 변경하지 않습니다.
- 자동 승인 검토가 실제 자료의 운영 API 전송·진단 세션 생성과 별도 임시 Worker 생성을 거절하여 두 작업 모두 실행하지 않았습니다. 운영 자료 등록은 수행하지 않았으며 실제 운영 등록 결과는 별도 확인이 필요합니다.

성능 개선 전반이나 벤치마크는 이번 변경에 포함하지 않습니다. 자료 등록을 실패시키는 반복 계산과 오류 처리만 수정합니다.
