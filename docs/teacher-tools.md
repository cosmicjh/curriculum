# 개인시간표·결보강의 공통 원본과 저장

- 저장소·운영 브랜치: `cosmicjh/curriculum`, `main`.
- 공개 주소: https://cosmicjh.github.io/curriculum/ . 교사 로그인 한 번으로 개인시간표·결보강·명렬표·학급 인쇄를 사용합니다.
- 관리자는 **자료 등록·선택분반·수업 연결·설정**에서 한 번만 수정합니다. 결보강에 별도로 교사나 시간표를 등록하지 않습니다. 이미 열린 화면은 조회·새로고침하거나 해당 탭을 다시 선택하면 최신 자료를 읽습니다.
- 두 기능은 같은 `school-timetable-db`의 활성 학기·교사 엑셀 원본·선택분반·수업 연결·요일별 교시를 읽습니다. 결보강용 시간표 사본을 저장하거나 두 DB를 동기화하지 않습니다.
- `src/class-swap-data.js`는 개인시간표의 같은 계산 결과를 결보강 규칙에 맞춰 표현합니다. 연속수업·선택과목·창체·공강 배정의 교체 제한을 보존하고, 교사 ID는 기존 이름 기반 규칙을 유지합니다.
- 기존 결보강 계획서는 ID·버전·상태·수업 스냅샷을 보존해 `swap_plans`로 이관합니다. 예약은 같은 DB의 `swap_reservations`에서 관리합니다. 현재 학기 자료만 조회하며, 다른 학기의 계획서를 덮어쓰거나 수정하지 못합니다.
- 예정된 결보강 계획의 교사·수업을 바꾸는 등록·수정·복원은 차단합니다. 해당 계획을 먼저 취소한 뒤 변경합니다. 과거 계획서는 원래 스냅샷을 보존합니다.
- 시간표 수정과 결보강 저장은 같은 DB 리비전·세션 검사와 D1 트랜잭션으로 보호합니다. 동시에 수정하면 한 요청만 반영되고 다른 요청은 새로고침을 요구합니다. 중복 예약·오래된 수정·취소도 차단합니다.
- 별도 결보강 계정·파생 세션·`CLASS_SWAP_DB` 바인딩을 사용하지 않습니다. 공통 비밀번호 변경·만료·로그아웃은 두 기능에 동일하게 적용됩니다.

## 화면과 인증

결보강은 `assets/class-swap/`의 네이티브 모듈이며 iframe·별도 문서·자동 로그인 화면이 없습니다. 스타일은 Shadow DOM으로 범위를 제한하고 글꼴·공통 세션·API·인쇄 영역을 시간표와 공유합니다. 세션 만료 시 공통 로그인 화면만 표시합니다. 임시저장한 초안은 학기별로 현재 탭에 보관하며, 새로고침한 뒤에도 해당 탭의 내 임시저장에서 열 수 있습니다. 로그아웃하거나 탭을 닫으면 사라집니다. 제출하면 공통 DB에 저장하고 제출 완료 화면에서 계획서·학급 공지를 인쇄할 수 있습니다. 제출 목록, 상세 조회와 취소는 관리자 메뉴에서 처리합니다. 교사에게는 중복 방지에 필요한 예약 교시만 제공합니다.

관리자 → 설정의 **교사 비밀번호 변경**, **관리자 비밀번호 변경** 버튼을 사용합니다. 기존 비밀번호·운영 자료를 재배포나 이관으로 초기화하지 않습니다. GitHub Pages 인증 토큰은 탭 메모리에만 보관합니다.

## 기존 운영 DB의 일회 이관

1. `pnpm test:all`을 실행합니다. 새 로컬 DB는 `pnpm db:migrate:local`로 현재 스키마를 적용하면 바로 사용할 수 있습니다.
2. `node scripts/migrate-class-swap.mjs`로 운영 자료를 읽기 전용 사전 검사합니다.
3. `node scripts/migrate-class-swap.mjs --apply`로 이관합니다. 두 DB 전체 SQL을 `private/`에 백업하고, 공통 DB 마이그레이션을 적용한 뒤 시간표 관리자 수정과 기존 결보강 DB의 업무 쓰기를 잠그고, 잠금 상태의 최신 전체 백업도 보관합니다. 계획서를 한 SQL 트랜잭션으로 복사하고 내용·예약 건수를 대조합니다. 복사 완료 전 실패하면 기존 DB 쓰기를 다시 허용합니다. 완료 이력이 있으면 재실행해도 다시 복사하지 않습니다.
4. `pnpm exec wrangler deploy --keep-vars`로 `school-timetable`을 배포합니다. 이관부터 배포가 끝날 때까지 결보강 저장을 잠시 중단합니다.
5. `pnpm exec wrangler deploy --config wrangler.class-swap-redirect.jsonc --keep-vars`로 이전 결보강 주소를 통합 화면으로 연결합니다. 구 API 쓰기는 410을 반환하며, 교사·자료를 별도로 등록하는 구 관리자 화면은 제공하지 않습니다.
6. 공통 Worker와 이전 주소 연결을 배포한 뒤 `node scripts/migrate-class-swap.mjs --release`로 관리자 수정을 재개합니다. 새 공통 데이터 버전이 실제 배포됐는지 확인한 후에만 잠금을 해제합니다.
7. `main`에 푸시하면 기존 Pages workflow가 두 기능을 함께 게시합니다. 배포 후 교사·수업 건수, 계획서 내용·예약, 계정 해시가 보존되었는지 확인합니다.

기존 `class-swap-db`는 활성 서비스에서 연결을 해제한 읽기 전용 복구 원본으로 보존합니다. 운영 자료를 담은 DB를 더미 자원으로 삭제하지 않습니다. 이전의 별도 DB 버전으로 코드를 되돌리면 새 계획서를 볼 수 없으므로 복구 시 공통 DB와 이관 이력을 함께 확인해야 합니다.

관리자 JSON 백업은 기존 개인시간표 원본 형식을 유지합니다. 결보강 계획서까지 포함하는 전체 복구본은 `wrangler d1 export DB --remote --output private/backup.local.sql`로 보관합니다. 운영 백업·비밀값·이관 로그·실제 자료는 Git과 정적 배포에서 제외합니다.

## 검증과 생성물

자동 시험은 가상 자료와 임시 D1 하나를 사용합니다. 단일 관리자 XLSX 등록이 두 화면에 반영되는지, 수업 연결·선택분반 수정, 예정 계획 보호, 시간표/계획 동시 수정, 학기 분리·초안 복원, 기존 계획 이관의 원자성과 예약 재생성을 검증합니다. 모바일·인쇄·세션·입력 보호 등 기존 회귀 검증도 유지합니다.

`vendor/class-swap/manifest.json`은 원본 계산·백업 규칙의 SHA-256과 이식한 클라이언트·저장 코드 위치를 기록합니다. 미사용 독립 서버·계정·스키마 구현은 제거했습니다. CI 결과는 실패 시에만 1일 보관하고, 운영 검증 후 로컬 시험 DB·번들·스크린샷·이전 Pages 산출물을 정리합니다. 자동 훅은 사용하지 않습니다.

## 이동수업 배치표

관리자 → 이동수업 배치표에서 교실·담임, 시간블록·교시, 과목·분반·담당 교사를 편집합니다. 교사 메뉴에는 열람·검색·인쇄만 제공합니다. 학기별 `room_allocations`는 같은 D1의 분반 ID를 참조하며, 교실 저장은 기존 `sections`를 함께 갱신합니다. 배치표에 연결된 분반의 교실은 배치표에서 변경합니다. [상세 사용 안내](room-allocations.md)
