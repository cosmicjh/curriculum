# Design: 시수배당 학기 전환 분리

Status: Approved by user (2026-11-19)

## Objective and scope

시수배당표의 학기 전환을 학교 설정 저장에서 분리해, 관리자 전용의 명시적인 "학기 전환" 동작으로 만든다.

## Current system and constraints

- 학교 설정 폼(`modules/allocation/app/workbook.js`의 school-form submit)에서 학년도·학기를 바꾸고 저장하면 확인 창 뒤 `POST /term`이 실행된다.
  서버(`modules/allocation/server/api.js`)는 현재 작업본을 `ca_term_archives`에 보관하고, 대상 학기의 보관본을 복원하거나 학급 수 0인 새 작업본을 만든다.
- 문제: 전환이 설정 저장 안에 숨어 있고 학급 수 등 다른 설정 변경과 섞인다. 통합시간표 활성 학기와 다를 때 알 수 없다.
- 시수배당 학기는 통합시간표 활성 학기와 독립이다(다음 학기를 미리 작업).

## Selected approach (사용자 결정 2026-11-19)

- 학기 연동: **독립 + 차이 표시**. 시수배당 학기는 따로 전환한다. 통합시간표 활성 학기와 다르면 머리에
  예: "통합시간표 2026-2" 같은 보조 표시를 둔다. 전환 창은 통합시간표 활성 학기를 기본 대상으로 제안한다(같으면 다음 학기).
- 버튼 위치: **머리의 학기 표시 옆**. 관리자에게만 텍스트 버튼 "학기 전환"(공통 UI 규칙: 텍스트 버튼, 회색조).
- 학교 설정의 학년도·학기 칸은 읽기 전용 표시로 바꾸고, 설정 저장은 학기를 바꾸지 않는다.
- 전환 창: 학년도·학기 선택, 대상이 보관본 복원인지 새 학기 생성인지 표시, 현재 작업본이 보관된다는 확인 문구.
  미저장 변경이 있거나 저장·로딩 중이면 전환을 막고 안내한다.
- 서버: 기존 `POST /term`의 보관·복원 의미와 버전·충돌 보호를 유지한다. 관리자 전용을 서버에서 보장한다.
  보관된 학기 목록과 통합시간표 활성 학기를 화면이 알 수 있도록 기존 응답 확장 또는 읽기 경로를 추가한다(DB 스키마 변경 없음).

## Rejected alternatives

- 통합시간표 학기 자동 추종: 다음 학기 미리 작업 불가(사용자 비선택).
- 학교 설정 화면 안 별도 버튼: 사용자 비선택.

## Compatibility and risks

- 데이터 형식·백업 schemaVersion·ID·`ca_` 스키마 변경 없음. 학기 보관·복원 결과는 기존과 동일해야 한다.
- 교사 화면에는 버튼이 없다. 서버는 교사의 `/term`을 거부한다.

## Testable acceptance conditions

- 관리자: 머리의 "학기 전환" → 대상 선택 → 확인 → 전환. 보관본 복원과 새 학기 생성 각각 시험.
- 학교 설정 저장은 학기를 바꾸지 않는다(학년도·학기 읽기 전용).
- 미저장 변경·저장 중에는 전환이 막힌다. 교사에게 버튼이 없고 서버도 거부한다.
- 활성 학기와 다를 때 차이 표시, 같을 때 표시 없음.
- 기존 시수배당·플랫폼 시험 전체와 UI 규칙 시험 통과.
