# Design: 분반배정 진급 학기 연계와 정원 초과 과목 처리

Status: Approved by user (2026-11-27)

`docs/design/section-assignment-term.md`를 잇는 설계다. 그 문서의 "다른 학기 학생 배정을 미리 저장하지 않는다" 결정은
이 문서가 대체한다. 나머지 결정(대상 학기 기본값, 학기 전환 UI, 시수 전달 경로)은 유지한다.

## Objective and scope

1. 통합시간표 운영 학기 2026-2(학생 학적 1학년)에서 2027-1 대상 학기로 분반배정한 결과를 처리한다.
   - 시수배당표에는 진급 학년(2학년)으로 바로 등록한다.
   - 학생 분반 배정은 2027-1에 저장한다. 진급 뒤 구학번 대응 파일로 2027-1 명부와 연결한다.
2. 분반 수를 줄여 과목 평균 인원이 공통 정원을 넘어도 분반배정을 실행한다.

DB 스키마·마이그레이션은 바꾸지 않는다.

## Current system and constraints

- 분반배정은 브라우저에서 계산한다. 서버와는 호스트 `assets/app.js`의 `window.sectionAssignmentConnect` bridge로만 통신한다.
  bridge는 `importHours`, `loadCourseSections`, `previewStudents`를 쓴다.
- `sheetGrade(sheet)`는 수강신청 파일 학생의 학적 학년을 시트 학년으로 쓴다. 이 값은 시수 전달의 `sheets[].grade`와
  확정 분반 수 불러오기 키에 쓰인다. 시수배당 가져오기(`modules/allocation/shared/hours-import.js`의 `plan`)는
  선택 학년이 원본 학년과 다르면 `원본의 대상 학년과 다릅니다`로 거부한다. 이것이 1번 오류의 원인이다.
- 학생 배정 전달(`stageToolTransfer kind:'students'`)은 화면과 서버 모두 운영 학기만 허용한다.
  연결(`previewImport`/`commitImport` + `transferRef`)은 `D.prepareImport(assignmentOnly)`로
  운영 학기 재학생을 학년-반-번호와 이름으로 찾는다. 하나라도 실패하면 반영하지 않는다.
- 학생 명부는 학기별(`students.term_id`)이다. 새 학기는 빈 명부로 시작하고 진급 명부는 관리자가 등록한다.
  진급하면 반·번호가 바뀐다. 따라서 저장 당시 학번으로는 새 명부와 연결할 수 없다.
- 실행 전 검사(`assets/section-assignment/app.js`)는 `신청 > 분반 수 × 공통 정원`이면 실행을 중단한다.
  엔진(`engine.js`)과 결과 검증은 모든 분반에 하나의 `maxPerSection`을 쓴다.
  공통 정원을 바꾸면 `recalcAllSectionsFromMax`가 모든 과목 분반 수를 다시 계산해 사용자가 줄인 분반 수가 사라진다.
  이것이 2번 오류의 원인이다.

## Selected approach (사용자 결정 2026-11-27)

### A. 대상 학년

- 시트의 대상 학년은 `학적 학년 + (대상 학기 학년도 − 운영 학기 학년도)`다.
  운영 학기는 통합시간표 운영 학기(`activeTerm`)다.
  예: 운영 2026-2, 대상 2027-1이면 1학년은 2학년이 된다. 같은 학년도면 학적 학년과 같다(기존 동작).
- 결과가 1–3 범위 밖이면 대상 학년을 `null`로 둔다(시수배당에서 직접 선택). 학적 학년이 시트 안에서 하나가 아니어도 `null`이다.
- 학생별 학적 학년의 출처 순서: 학년 열 → 5자리 학번 첫 자리 → 시트명의 "N학년".
  이 값은 대상 학년 계산과 학생 배정 자료에 쓰는 별도 값이다.
  기존 파서의 학생 `grade` 필드, 설정 fingerprint와 결과 엑셀은 바꾸지 않는다. 기존 설정 JSON 복원을 보존해야 한다.
  (독립 검토 반영 2026-11-27)
- 대상 학기 확인 전에는 대상 학기에 의존하는 시수 JSON 내려받기도 잠근다. 파일 선택·계산·결과 엑셀은 허용한다.
- 대상 학년은 다음 경로에 함께 쓴다.
  - 시수 전달(`sheets[].grade`)과 JSON 내려받기.
  - 시수배당 확정 분반 수 불러오기의 학년 키.
- 학적 학년은 결과 엑셀의 학생 명단과 학생 배정 자료에 그대로 둔다.
- 대상 학년이 학적 학년과 다르면 분반배정 화면에서 짧게 알 수 있게 한다(예: 시트 행에 "2학년(학적 1학년)").
  불필요한 안내 문구는 넣지 않는다.
- `hours-import.js`의 원본 학년 일치 검사는 유지한다. 원본 학년이 진급 학년으로 바뀌므로 2학년 선택이 통과한다.
- 학년 접두 코드(예: `1A`, `1A2`)도 대상 학년이 학적 학년과 다를 때 시수 전달·JSON에서만 진급 학년 접두(`2A`, `2A2`)로 바꾼다.
  바꾸는 대상은 `timeBlocks[].code`, `timeBlock`, `sectionCode`, 결합 정보다. 전달 자료 안의 참조는 서로 일치해야 한다.
  접두가 학적 학년과 같을 때만 바꾸고, 그 밖의 코드는 그대로 두어 기존 검사가 판단한다.
  분반배정 시트 설정, 결과 엑셀과 학생 배정 자료의 코드는 바꾸지 않는다.
  학생 배정의 분반 코드 검사(`^[A-Z]+[0-9]*$`)는 기존과 같다.
  (구현 중 확인 2026-11-27)

### B. 다른 학기 학생 배정 저장

- 분반배정에서 대상 학기가 운영 학기와 다르면 학생 버튼이 "학생 배정 저장"으로 바뀐다.
  이 버튼은 미리보기 없이 대상 학기에 저장만 한다. 완료 상태는 짧은 문구로 보인다(예: "2027-1 학생 배정 N명 저장").
  같은 학기면 기존 "학생 배정 미리보기" 흐름을 그대로 쓴다.
  계산·전송·학기 확인 중 잠금은 기존 규칙을 따른다.
- 저장 자료는 학생별 학적 학년·반·번호, 이름과 과목별 분반 코드다. 기존 `studentRows` 검증을 그대로 쓴다.
  저장 당시 운영 학기(`sourceTerm`)도 함께 둔다.
- 서버 `stageToolTransfer kind:'students'` 규칙:
  - 운영 학기는 기존과 같다.
  - 운영 학기가 아닌 학기는 관리자만, `validTerm`이고 운영 학기보다 뒤인 학기만 허용한다.
  - 진급 학년(학적 학년 + 학년도 차이)이 3을 넘는 학생이 있으면 거부한다.
  - 학기가 없으면 hours와 같은 방식으로 `INSERT OR IGNORE INTO terms`를 쓴다. 운영 학기와 쓰기 가드는 바뀌지 않는다.
  - 같은 학기에 다시 저장하면 덮어쓴다(기존 동작).
- 저장 형식은 기존 배열 자료와 호환해야 한다. 기존 배열 자료는 `sourceTerm`이 전달 학기와 같은 것으로 읽는다.
  건수 조회(`readToolTransfer`)는 두 형식 모두에서 맞아야 한다.

### C. 진급 후 연결(구학번 대응 파일)

- 진급 연결 대상은 `sourceTerm` 학년도가 전달 학기 학년도보다 앞선 학생 전달 자료다.
  연결은 그 전달 학기가 운영 학기일 때 학생 메뉴의 "서버 분반배정"에서 한다.
  순서: 운영 학기를 2027-1로 전환한다 → 진급 명부를 등록한다 → 연결한다.
- 진급 연결 자료면 미리보기 전에 구학번 대응 파일(XLSX/CSV)을 받는다.
  - 열: `구학번`, `신학번`(또는 `학번`), `이름`. 학번은 5자리다.
  - 구학번·신학번이 중복되거나 형식이 틀리면 파일 전체를 거부한다.
- 서버가 대응을 적용한다. 미리보기와 반영 요청에 같은 대응표를 보낸다.
  기존 `transferRef` 변경 검사(`TRANSFER_CHANGED`)는 유지한다. 저장 학생별로 아래를 모두 만족해야 연결한다.
  1. 대응표에 저장 학생의 구학번이 있고 이름이 같다.
  2. 신학번 학년이 기대 진급 학년과 같다.
  3. 운영 학기 재학생 중 그 신학번의 학생이 있고 이름이 같다.
- 대응표는 3,000행까지, 파일은 5MB까지 받는다. 서버도 행 수를 다시 검사한다.
- 하나라도 실패한 학생은 연결에서 제외하고 사유를 미리보기에 목록으로 보인다.
  사유: 대응 없음, 이름 불일치, 진급 학년 불일치, 명부 없음 등. 나머지 학생은 반영한다.
  연결된 학생이 0명이면 오류다. 제외된 학생은 학생 수정 화면에서 직접 입력한다.
- 연결된 학생은 기존 `prepareImport(assignmentOnly)` 규칙으로 반영한다.
  수동 배정 보호 충돌, 분반 추론과 자동 백업이 이에 포함된다.
- 진급이 아닌 학생 전달 자료(같은 학년도)는 기존처럼 학번과 이름이 정확히 일치해야 하고, 하나라도 실패하면 반영하지 않는다.

### D. 정원 초과 과목

- 공통 정원으로 신청 인원을 수용할 수 없는 과목(`신청 > 분반 수 × 공통 정원`)은 실행을 막지 않는다.
  그 과목 분반만 정원을 `ceil(신청 ÷ 분반 수)`로 올린다. 다른 과목은 공통 정원을 쓴다.
- 실행 로그에 상향한 과목·신청·분반 수·적용 정원을 경고로 보인다.
- 엔진의 배정·이동·재균형 단계, 엔진 검증, 앱 `validateResult`, 결과 엑셀, 시수 전달의 `capacity`는
  모두 분반별 적용 정원을 쓴다.
  - 서버의 시수 전달 저장본은 지금처럼 `capacity`를 정규화 과정에서 버린다. 시수배당은 정원을 쓰지 않는다.
- 2+1 결합 분반은 연결된 두 분반 정원 중 작은 값을 쓴다.
  이 때문에 상향 정원이 제한되면 해당 결합과 적용 정원을 경고로 보인다.
- 공통 정원 입력과 `recalcAllSectionsFromMax` 동작은 바꾸지 않는다. 설정 저장 형식(schema 3)도 바꾸지 않는다.
- 학점·코드 수용·기대 총학점·커버리지·대분반·2+1 결합 같은 다른 제약은 그대로다.

## Rejected alternatives

- 이름으로 자동 연결: 동명이인 위험 때문에 사용자가 구학번 대응 파일을 골랐다.
- 하나라도 연결 실패 시 전체 중단(진급 연결): 전출 등으로 실패가 흔할 수 있다. 제외 목록을 보이고 나머지를 반영한다.
- 공통 정원 전체 상향, 실행 전 확인 창: 사용자가 해당 과목만 자동 상향을 골랐다.
- 시트 대상 학년을 사람이 직접 고르기: 학년도 차이로 결정할 수 있다. 시수배당 가져오기에서 학년을 다시 확인한다.
- 학생 테이블에 구학번 열 추가: 스키마 변경이 필요하다. 연결할 때 대응 파일로 충분하다.

## Compatibility, privacy and migration risks

- 스키마·마이그레이션·백업 형식·학생/분반 ID는 바꾸지 않는다. `school-course-hours` 형식은 바꾸지 않는다(`grade` 값의 의미만 대상 학년).
- 학생 개인정보(학번·이름·선택 분반)가 운영 학기가 아닌 학기의 `tool_transfers`에 저장된다.
  관리자만 저장·조회·연결할 수 있다. 같은 학기 재저장으로 덮어쓴다. 교사·비인증 요청은 거부한다.
- 구학번 대응 파일은 서버에 저장하지 않는다. 요청 처리에만 쓴다.
- 정원 상향 과목은 공통 정원보다 많은 학생이 배정된다. 로그와 결과에 적용 정원을 남긴다.
- 고위험 변경(학생 데이터 처리, 배정 제약)이므로 병합 전에 새 Codex 스레드로 독립 검토한다.

## Testable acceptance conditions

- 대상 학년: 운영 2026-2, 대상 2027-1, 학적 1학년 시트의 시수 전달 `grade`가 2다.
  시수배당을 2027-1로 두고 2학년으로 가져오기가 성공한다. 같은 학년도면 학적 학년이다.
  범위 밖이면 `null`이다. 확정 분반 수 불러오기는 대상 학년 키를 쓴다.
- 서버(API):
  - 운영 2026-2에서 학생 전달 저장 `term:'2027-1'`이 성공한다. 2027-1 학기가 생기고 운영 학기는 유지된다.
  - 다음은 거부한다: 과거 학기, 잘못된 학기, 진급 학년이 3을 넘는 학생, 교사·비인증 요청.
  - 운영 학기 저장과 같은 학기 연결은 기존 시험대로 통과한다.
- 진급 연결:
  - 2027-1로 전환하고 반·번호가 바뀐 2학년 명부를 등록한 뒤 대응표로 미리보기·반영하면 연결된 학생의 선택 분반이 들어간다.
  - 대응 없음, 이름 불일치, 학년 불일치, 명부 없음은 제외 목록에 사유와 함께 나오고 나머지는 반영된다.
  - 중복·형식 오류 대응표는 거부한다. 대응표 없이 진급 자료 미리보기는 거부한다. 전달 자료가 바뀌면 `TRANSFER_CHANGED`다.
- 정원:
  - 한 과목의 분반 수를 줄여 평균이 공통 정원을 넘으면 실행이 시작되어 검증을 통과한 완전배정 결과가 나온다.
  - 그 과목 분반 인원은 `ceil(신청 ÷ 분반 수)` 이하이고, 다른 과목은 공통 정원 이하다.
  - 로그에 상향 경고가 나오고, 엔진 검증은 분반별 정원 초과를 여전히 잡는다.
- 브라우저: 다른 학기에서 "학생 배정 저장"이 활성화되어 저장되고, 같은 학기에서는 기존 미리보기가 유지된다.
  진급 연결 흐름은 대응 파일 선택, 미리보기 제외 목록, 반영 순서로 진행된다.
  키보드 조작과 390px 화면을 확인한다.
