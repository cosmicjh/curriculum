# Design: 스터디룸 목록 정렬·학년 필터·표 밀도와 접속 집중 시 제출 누락 방지

Status: Approved by user (2026-11-23)

## Objective and scope

1. 목록(현재 출석의 `목록` 보기, 출석 조회 결과 표)에 열 정렬을 추가한다.
2. 같은 목록의 표 우측 상단에 학년 단일 선택(`전체 · 1학년 · 2학년 · 3학년`)을 추가한다.
3. 같은 목록 표의 셀 위아래 내부 여백을 줄여 표를 타이트하게 한다.
4. 접속이 몰릴 때 학생 출석 등록이 누락되는 경로를 막는다.

범위 밖: 좌석 배치표 보기, 운영 설정, 교사 수동 등록·정정 흐름, DB 스키마·마이그레이션, 다른 모듈의 통신 동작, 운영 로그(사용자 결정: 켜지 않음).

## Current system and constraints

- 교사 화면 `assets/studyroom.js`의 `mountStudyroom`. `table(rows,query)`가 현재 출석 목록과 출석 조회 표를 함께 그린다(열: 학번·이름·좌석·제출·비고).
  출석 조회는 `groupedTable`로 날짜→회차별 표를 여러 개 그리고 서버에서 200건씩 페이지로 받는다. 현재 출석은 `refreshSeconds`(기본 30초)마다 `dashboard`를 다시 받아 `paintCurrent`로 다시 그린다.
- 표 스타일 `assets/studyroom.css`: 데스크톱 `.sr-table td,.sr-table th{padding:12px}`, `td{line-height:24px}`. 920px 이하 `padding:6px 3px`.
  `test:ui`는 버튼 최소 높이 데스크톱 32px, 640px 이하 44px을 검사한다. 모든 버튼은 테두리·배경 없는 텍스트 버튼, 모노톤·Pretendard.
- 학생 제출: `studyroom-student.html` + `assets/studyroom-student.js` → `TTApi.request('studyroom',{op:'submit',requestId,...})`(`assets/transport.js`, 제출 시간 제한 110초, 교사용 실패 문구).
  `requestId`는 `sessionStorage`(회차·좌석·학번 키)에 보관되어 같은 입력의 재제출은 멱등이다.
- 서버 `src/studyroom.js`의 `student()`: 3회 루프. `sr_revision_conflict`·`sr_record_conflict`·`(session_id,person_id)` UNIQUE만 재시도하고, 실패 후에는 항상 `replay(requestId)`로 이미 저장된 결과를 먼저 확인한다.
  그 밖의 오류는 그대로 던져져 `src/worker.js`에서 500 "서버 설정 또는 처리를 확인하세요."가 된다. `sr-student` 요청 제한은 IP당 분당 600회이며 학교 NAT는 IP 하나를 공유한다.
- 쓰기 가드 트리거(0006): 학생 쓰기도 `app_state.revision`(시간표 수정 시 증가)·`policy_revision`·활성 학기가 같아야 하며, 마감된 회차는 `sr_session_closed`로 거부한다.

### 누락 원인 분석

로컬 99명 동시 제출 시험은 통과하며, 성공 응답 뒤 기록이 사라지는 서버 경로는 코드에서 찾지 못했다. 운영 로그가 없어(`observability.enabled:false`) 실제 원인은 확정할 수 없다. 학생이 제출하지 못한 채 떠날 수 있는 경로는 다음과 같다.

- A. D1 일시 오류(과부하·연결 끊김·제한 초과, Worker 한도 503)가 재시도 없이 학생에게 일반 500 또는 비JSON 응답으로 표시된다.
- B. 학생 화면에 제출 중 표시가 없고 최대 110초를 기다린다. 화면을 닫거나 잠그면 요청이 끊긴다.
- C. 실패 문구가 교사용("자료 목록에서 저장 여부를 확인")이고 자동 재시도가 없다.
- D. 시간표 저장과 겹치면 `sr_revision_conflict`가 3회 연속 날 수 있고, 그 뒤 500이 된다.
- E. 회차 종료 경계의 `sr_session_closed`가 해석되지 않은 500이 된다.

## Selected approach

### 목록 UI (`assets/studyroom.js`, `assets/studyroom.css`)

- 정렬: 학번·이름·좌석·제출 열 머리글을 텍스트 버튼으로 만든다. 같은 열을 다시 누르면 오름차순↔내림차순, 다른 열을 누르면 그 열의 오름차순이다.
  `th`에 `aria-sort`를 표시하고 기본은 학번 오름차순이다. 같은 값은 학번으로 순서를 고정한다. 이름은 `localeCompare('ko')`, 제출은 `first_at` 시각을 기준으로 한다.
  출석 조회에서는 날짜·회차 묶음 순서는 유지하고 각 묶음 안에서 정렬한다. 정렬은 불러온 행에만 적용한다(페이지 단위).
- 학년: 표 우측 상단 툴바에 기존 `toggleGroup`과 같은 형식의 단일 선택을 둔다. 학년은 `student_number` 첫 자리다.
  현재 출석은 `목록` 보기일 때만 보이며, 출석 인원 표기는 필터 적용 시 `1학년 30명 / 전체 99명`처럼 함께 표시한다. 좌석 보기는 바꾸지 않는다.
  출석 조회는 날짜 기록 표 위에 둔다. 한 학생의 기록 보기에서는 숨기며, 걸러진 결과가 없으면 `기록 없음`을 표시한다.
- 정렬과 학년 상태는 자동 새로고침·저장 후 다시 그리기·페이지 이동에도 유지한다. 보기 전환 시 유지 여부는 구현이 단순한 쪽을 택하되 현재 출석과 출석 조회의 상태가 서로 섞이지 않게 한다.
- 여백: 데스크톱 `.sr-table` 셀의 위아래 여백을 4px로 줄인다(좌우 유지). 920px 이하는 위아래 4px 이하로 줄인다. 버튼 최소 높이 규칙(32px/44px)은 유지한다.
  기준 해시가 고정된 `style.css`는 변경하지 않는다.
- 키보드: 정렬 버튼과 학년 토글은 Tab·Enter·Space로 조작되고 상태(`aria-sort`, `aria-pressed`)가 스크린리더에 전달된다.

### 제출 누락 방지 (출석 고위험 변경)

- 서버(`src/studyroom.js` 학생 경로만):
  - 기존 루프의 재시도 대상에 D1 일시 오류(메시지 패턴은 구현 시 Cloudflare 문서 기준으로 정하고 시험으로 고정)를 추가한다.
    `sr_revision_conflict`·`sr_record_conflict`와 함께 지터가 있는 짧은 지연(합계 약 1초 이내)으로 최대 5회까지 시도한다. 재시도·응답 전에는 항상 기존 `replay`를 먼저 확인한다.
  - 재시도를 모두 실패하면 503 `SR_RETRY`("접속이 많아 저장하지 못했습니다. 출석 제출을 다시 누르세요.")를 돌려준다.
    `sr_session_closed`는 409 `CLOSED`("회차가 마감되었습니다. 교사에게 확인하세요.")로 돌려준다.
  - 요청 제한(`sr-student`)의 실패도 학생 화면에서 재시도할 수 있게 429 응답을 유지한다. 제한값은 99석×(확인+제출+재시도)를 고려해 부족하면 조정한다.
  - 저장 형식·이벤트·가드 트리거·`replay` 의미는 바꾸지 않는다.
- 학생 화면(`assets/studyroom-student.js`, 필요하면 `studyroom-student.html`·`assets/studyroom.css`):
  - 제출 중에는 `제출 중…`을 `role=status`로 표시하고 버튼을 잠근다.
  - 제출 한 번의 응답 대기는 약 20초로 줄인다.
    연결 실패·시간 초과·비JSON 5xx·503 `SR_RETRY`·429일 때 같은 `requestId`로 자동 재시도한다(최대 4회, 지수 백오프+지터, 429는 `Retry-After`를 존중). 재시도 중에는 `다시 제출하는 중…(n/4)`를 표시한다.
  - 재시도를 모두 실패하면 학생용 문구("제출이 확인되지 않았습니다. 출석 제출을 다시 누르세요.")를 보인다. `requestId`는 그대로 두어 다시 눌러도 멱등이다.
  - 재시도 불가 오류(`SEAT_OCCUPIED`, `NOT_ELIGIBLE`, `SESSION_CHANGED`, `CLOSED`, `REQUEST_REUSED`, `TERM_CHANGED`, 400)는 즉시 표시하고 재시도하지 않는다.
  - `이름 확인`(`studentInfo`)에도 같은 제한 시간과 일시 오류 재시도를 적용한다(읽기 전용).
- `assets/transport.js`: 다른 모듈 동작은 바꾸지 않는다. 필요한 경우에만 최소 변경(시간 초과 오류에 `code` 부여, 호출자별 제한 시간 옵션)을 허용하며 기존 호출의 기본값·문구는 유지한다.

## Rejected alternatives

- 쓰기 가드 트리거에서 학생 쓰기의 `tt_revision` 검사 제거: 원인 D를 근본적으로 없애지만 마이그레이션이 필요한 고위험 변경이다. 재시도로 충분히 완화되므로 보류한다.
- 서버 정렬·학년 필터(쿼리 파라미터): 페이지 단위 정렬 한계를 없애지만 API를 바꾸고, 하루 200건을 넘는 경우가 드물어 이득이 작다.
- 운영 로그 활성화: 원인 확정에 도움이 되지만 사용자가 개인정보 노출 위험을 이유로 선택하지 않았다.

## Compatibility and risks

- 출석 데이터·이벤트·백업(`export`) 형식, ID, 버전·충돌 보호, `requestId` 멱등성은 유지한다. 마이그레이션 없음.
- 실제 원인이 확인되지 않았으므로, 학생에게 `제출 완료`가 보였는데 기록이 없는 사례가 다시 생기면 별도 서버 조사가 필요하다.
- 학생이 응답 전에 화면을 닫으면 여전히 제출되지 않을 수 있다. 제출 중 표시와 짧은 제한 시간으로 완화만 한다.
- 출석 조회 정렬·필터는 불러온 페이지(최대 200건) 안에서만 적용된다.
- 자동 재시도는 요청 수를 늘린다. 요청 제한과 D1 부하를 시험으로 확인한다.

## Testable acceptance conditions

- 정렬: 현재 출석 목록과 출석 조회 표에서 학번·이름·좌석·제출 머리글 버튼으로 오름·내림 정렬되고 `aria-sort`가 바뀐다. 자동 새로고침 뒤에도 정렬이 유지된다.
- 학년: `1학년`을 고르면 학번이 1로 시작하는 행만 보이고 인원 표기가 갱신된다. `전체`로 되돌릴 수 있고, 새로고침 뒤에도 선택이 유지된다. 출석 조회의 학생 기록 보기에서는 학년 선택이 보이지 않는다.
- 여백: 데스크톱 1280px에서 `.sr-table td`의 위아래 padding이 4px 이하다. `test:ui`의 버튼 최소 높이(32px/44px)가 통과한다. 640px 폭에서 가로 넘침이 늘지 않는다.
- 서버: 첫 commit 직전에 D1 일시 오류를 주입하면 제출이 성공하고 기록 1건·`submit` 이벤트 1건만 남는다.
  commit은 성공했지만 오류가 난 경우에는 `replay`로 같은 응답이 오고 중복 기록이 없다. `sr_revision_conflict`가 4회 연속이어도 성공한다. 재시도를 모두 실패하면 503 `SR_RETRY`, 마감 회차면 409 `CLOSED`가 온다.
- 학생 화면(브라우저): 제출 응답을 1~2회 실패(네트워크 오류·503·시간 초과)시키면 자동 재시도 후 `제출 완료`가 표시되고 기록이 1건이다. `SEAT_OCCUPIED`는 재시도 없이 즉시 표시된다. 제출 중 표시가 보인다.
- 기존 99명 동시 제출 시험(같은 NAT IP)이 통과하며, 재시도 경로를 포함한 동시 제출에서도 중복 점유와 누락이 없다.
- 시간표 저장과 학생 제출을 동시에 실행해도 모든 제출이 성공한다.
- `pnpm test:all` 전체 통과. 검증 계약·불변조건 테스트는 변경하지 않는다.
- 병합 전 새 Codex 스레드에서 설계·검증 계약·코드·시험을 대조하는 독립 검토를 받는다.

## Implementation decisions (2026-11-23, 조정자 · 승인 범위 내)

- `src/worker.js`: 500 문구 덮어쓰기 예외에 `SR_RETRY` 추가. 스터디룸 학생 op(`studentInfo`·`submit`)의 D1 일시 오류(`S.context`·`rateLimit` 포함)는 503 `SR_RETRY`로 응답한다(같은 `requestId` 재시도가 멱등). 확정된 4xx 업무 오류는 가리지 않는다.
- 학생 op의 429에만 `Retry-After`를 CORS로 노출하고, 값은 실제 남은 제한 창(초)이다. 다른 경로의 `Retry-After`(60)는 유지한다. `sr-student` 한도는 최악 재시도(99석 × 확인·제출)를 고려해 1200/분으로 올린다.
- 학생 화면: 요청당 제한 시간 20초와 전체 재시도 예산(약 60초)을 분리한다.
- 이름 확인-제출 결속: `studentInfo`가 내부 ID를 드러내지 않는 학생 키를 주고, `submit`의 키가 현재 학번의 학생과 다르면 409 `STUDENT_CHANGED`로 거부한다. 키가 없는 옛 화면 요청은 기존처럼 처리하며 fingerprint는 바꾸지 않는다.
- D1 "10초 자원 한도" 오류는 서버 내부 재시도에서 제외하고 즉시 503 `SR_RETRY`로 돌려준다.
- 출석 조회는 같은 날짜·같은 이름 회차를 `session_id`로 구분해 표시한다.
- `tests/fixtures/ui-baseline.json`의 `assets/studyroom.css` 해시 한 줄을 갱신한다(`docs/VALIDATION.md` 37행 절차, 시험 코드 무변경).
- 학생 키는 replay에도 적용한다. 보류 요청의 저장 키에 학생 키를 포함하고, 키가 있는 replay는 저장된 이벤트의 학생 키와 같을 때만 결과를 돌려준다.
- 학생 키는 SHA-256 결속값이며 HMAC을 쓰지 않는다. 인증 비밀이 아니고, 제출은 원래 학번만으로 가능하므로 키를 예측할 수 있어도 새 권한이 생기지 않는다.
